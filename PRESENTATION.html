Problem Statement & Motivation

The Academic Mentoring Dilemma

1. Student Ambiguity & Creep
  • •Vague Scopes: Over-ambitious topics without boundary limits.
  • •Scope Creep: Features multiply mid-semester, causing abandoned codebases.
  • •Stack Mismatch: Frameworks picked without considering team skills.
  • •Result: High failure rates and rushed final submissions.
2. Faculty Supervision Bottleneck
  • •High Ratio: 1 guide supervising 10–25 student teams.
  • •Feedback Latency: 2–3 weeks delay on proposal reviews.
  • •Zero Visibility: Guides spot team blockers only at mid-term vivas.
  • •Admin Drag: 70% of time spent reviewing basic document formatting.
3. Institutional Fragmentation
  • •Scattered Tools: Progress tracked in WhatsApp, emails, and Excel.
  • •No Audit Trail: Absence of structured milestone verification.
  • •Subjective Scoring: Lack of objective feasibility benchmarks.
  • •Our Vision: Centralized AI platform bridging students and faculty.
The Proposed Innovation

Autonomous Multi-Agent Mentoring Ecosystem

Multi-Agent Workflow

Autonomous Agent Chain-of-Thought Flow

End-to-End Agent Chaining Pipeline
  • 1.Proposal Ingestion: Student submits idea, team size, duration, and self-assessed skill proficiencies.
  • 2.Agent 1 (Feasibility Check): Computes 0-100 score across complexity, timeline, and skill match; identifies bottlenecks.
  • 3.Agent 2 (Scope Governance): Ingests Feasibility report; enforces strict In-Scope vs Out-of-Scope boundaries.
  • 4.Agent 3 (Tech Stack Recommender): Ingests Scope & Skills; recommends frontend, backend, DB, and devops tools with trade-offs.
  • 5.Agent 4 (Risk Matrix Agent): Ingests Tech Stack & Scope; scores Technical, Deadline, and Operational risks with mitigations.
  • 6.Agent 5 (Milestone Tracking Agent): Synthesizes reports into a 5-Phase structured execution roadmap with task criteria.
  • 7.Agent 6 (Dynamic Re-Planner): Continuously monitors task velocity and reschedules downstream tasks on delay.
  • 8.Agent 7 & 8 (Doc Gen + AI Mentor): Generates Project Synopsis drafts and provides 24/7 interactive voice mentoring.
Agent Deep Dive: Inception

Agent 1: Feasibility Check & Agent 2: Scope Governance

Agent 1: Feasibility Check Agent
  • •Role: Senior Academic Research & Technical Reviewer.
  • •Vectors: Technical complexity, timeline viability, resource availability, skill readiness.
  • •Outputs: 0–100 Score, Verdict (Highly Feasible / Feasible with Guidance / Needs Scope Reduction).
  • •Actionable Insights: Top 3 strengths, top 3 bottlenecks, and required skill upgrades.
  • •Resiliency: Heuristic fallback ensures scoring even under network throttling.
Agent 2: Scope Definition Agent
  • •Role: Software Architect & Agile Product Manager.
  • •Input Chaining: Ingests upstream Feasibility report to address bottlenecks.
  • •Anti-Creep Safeguards: Delineates mandatory In-Scope features vs Out-of-Scope non-goals.
  • •Core Deliverables: Problem statement, 3+ measurable objectives, target user personas.
  • •Grounding: Eliminates scope creep before code development begins.
Agent Deep Dive: Architecture & Risk

Agent 3: Tech Stack Recommender & Agent 4: Risk Matrix

Agent 3: Tech Stack Recommender
  • •Role: Full-Stack Technology Strategist.
  • •Skill-Aware Matching: Maps frameworks against student skill proficiencies.
  • •Stack Coverage: Frontend, Backend, Database, Hosting, and CI/CD tools.
  • •Trade-off Analysis: Compares primary selections with industry alternatives.
  • •Ramp-up Roadmap: Curates targeted learning resources for skill gaps.
Agent 4: Multi-Vector Risk Assessment
  • •Role: Infrastructure & Project Risk Analyst.
  • •Vectors: Technical complexity, deadline pressures, and external dependencies.
  • •Scoring: Probability (1-5) × Impact (1-5) ➔ Risk Level (Low/Medium/High).
  • •Mitigations: Step-by-step preventative actions and early warning signs.
  • •Contingency: Architectural fallback plans if third-party APIs fail.

Security & Resiliency

Security, Resiliency & Fallback Architecture

Security & Access Governance
  • •Role-Based Access Control: Strict separation of Student and Faculty roles.
  • •JWT Session Tokens: Cryptographically signed tokens protecting private routes.
  • •Data Isolation: Projects and chat logs partitioned strictly by user ID.
  • •Credential Hygiene: All API keys and secrets isolated in `.env` files.
  • •Input Sanitization: Strict Pydantic models guard against prompt injection.
Resiliency & Offline Continuity
  • •Dual-Persistence: MongoDB Atlas primary with automatic local JSON fallback.
  • •Startup Health Hooks: Automatic database ping with detailed diagnostics.
  • •LiteLLM Fallback: Automatically cascades to alternate models on rate limits.
  • •Rule-Based Heuristics: Computes valid reports even if LLM is unreachable.
  • •Optimistic UI: Instant frontend state updates with background synchronization.
